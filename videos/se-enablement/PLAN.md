# MariaDB AI Plugins — SE Enablement Video: how it is made

A 132-second (131.7 s), 1080p30 motion-graphics video for **MariaDB plc Sales Engineers**:
what the MariaDB AI Plugins are, why they matter to customers who are moving to
agent-driven development, how they are installed, and four real scenarios from
the DevHub tutorials. It is narrated by a US English neural voice, with music and
sound design under it and burned-in captions.

Everything here is generated from source: nothing is edited by hand in a video
tool. To change the video, edit a source file and re-run a step below. The
sources in this folder are tracked in git. The shared toolchain (`videos/.cache/`),
this video's intermediates (`.work/`, `src/vo.wav`, `src/timeline.*`) and the
rendered files in `videos/output/` are generated and gitignored. See
[../README.md](../README.md) for the shared setup.

## Outputs

Both land in `videos/output/`.

| File | What |
| --- | --- |
| `MariaDB-AI-Plugins-SE-Enablement.mp4` | Final video: H.264 1920×1080 30 fps (CRF 16), AAC 256k stereo, −16 LUFS integrated, faststart |
| `MariaDB-AI-Plugins-SE-Enablement.srt` | The same captions as a sidecar file, for an LMS or a player with captions off |

## Pipeline

```text
src/narration.json ──tts.py (Kokoro)──▶ src/vo.wav + src/timeline.json   (sentence + word times)
                                              │
src/index.html + timeline.js ──render.py──────┤──▶ .work/video.mp4 (silent)  + .work/sfx.json + .srt
                                              │
.work/sfx.json + timeline + vo ──audio.py─────┴──▶ .work/mix.wav
                                     ffmpeg mux + loudnorm ──▶ ../output/MariaDB-AI-Plugins-SE-Enablement.mp4
```

The **narration drives everything**. `tts.py` synthesizes one sentence at a time,
so the exact start and end of every sentence are known. It estimates each word's
time within a sentence from its character position. The animation page and the
sound design both take their timing from those cues, so when you change a line,
everything after it moves along with it.

```sh
./build.sh            # everything: narration, check, frames, audio, mux
./build.sh --no-tts   # keep the current narration (visual / audio changes only)
```

`build.sh` runs `../setup.sh` first if the shared toolchain is missing. From a
clean checkout, a full build takes about 3 minutes on an M4 Pro: frame capture
runs on seven Chrome workers, and the TTS and audio steps take under 30 s each.
The narration is reproducible: re-synthesizing the same `narration.json` with the
pinned toolchain gives a byte-identical `timeline.json`, which is why `vo.wav`
and `timeline.json` are not tracked.

Rendering uses the installed **Google Chrome** (`channel="chrome"`), so there is
no Playwright browser download. The page loads Lato and IBM Plex Mono from Google
Fonts, so a render needs network access; `render.py check` reports whether both
fonts loaded.

**Gotcha — espeak-ng data path:** espeak-ng silently rejects a data path longer
than 160 characters and falls back to a compiled-in CI path
(`/Users/runner/work/espeakng-loader/...`), which fails with "Error processing
file … phontab". The venv's own copy sits too deep, which is why `tts.py` points
at the short `videos/.cache/esd` copy that `setup.sh` makes. Passing the parent directory doesn't work either:
it must be the `espeak-ng-data` directory itself.

## Narration

- **Voice:** Kokoro v1.0 `af_heart` (US English, female), the highest-rated
  Kokoro voice. **Speed 1.05.** It runs locally, so nothing is sent to a cloud
  service. Alternatives to try: `af_bella`, `af_nicole`, or the male voices
  `am_michael`, `am_fenrir` and `am_puck`. Call it as `src/tts.py <voice> <speed>`.
- **macOS `say` instead:** only the standard voices are installed on this Mac,
  and they sound robotic. If you install *Ava (Premium)* or *Evan (Premium)*
  (System Settings → Accessibility → Spoken Content → Manage Voices), you can
  swap the `k.create(...)` call in `tts.py` for
  `say -v "Ava (Premium)" -o x.aiff "<sentence>"` + read it back. The rest of the
  pipeline stays the same, since it only needs per-sentence audio.
- **Spelling for the voice:** Kokoro reads some words badly, so `narration.json`
  spells them out phonetically and the captions translate them back
  (`capText()` in `index.html`):

  | Written for the voice | Caption shows |
  | --- | --- |
  | `Maria-DB` | MariaDB |
  | `AI-Plugins` | AI Plugins |
  | `My S Q L` | MySQL |
  | `M C P` | MCP |
  | `thirty-three ten` | 3310 |
  | `version one point one` | version 1.1 |
  | `Maria-DB dot com slash docs` | mariadb.com/docs |

  When you add a word that needs this, add it in both places.

  Write the name as **`Maria-DB`**, not `Maria DB`. With a space, espeak makes
  two phoneme words (`mɚɹˈiːə dˌiːbˈiː`) and the voice pauses for about 60 ms
  between "Maria" and "DB". With the hyphen, it is one word,
  `mɚɹˈiːədˌiːbˈiː`, said in one go with the stress on "DB". `Mariadb` also
  joins the word, but it loses the stress on "B".

  **`AI-Plugins`** works the same way. As two words, there is a 181 ms gap
  between "AI" and "Plugins"; joined, there is none. The voice then takes a
  166 ms breath before the word instead, after "MariaDB". The title animation
  cues off the joined word (`reveal:ai-plugins-0.1`).
- **Timed pauses:** `{pause:0.2}` in the script sets a pause of exactly that many
  seconds. `tts.py` speaks the marker as a comma, which gives a natural slight
  lift before it. It then finds that comma's silence, the longest quiet run near
  the marker's position, and cuts or pads it to the requested length, with 5 ms
  fades. It prints `pause 287 ms -> 200 ms` for each marker. The captions and
  `timeline.json` never contain the marker. It is **not used at the moment**:
  it was tried as "the Maria-DB {pause:0.2} AI Plugins close", but even 200 ms
  was too long there, so that line is back to no pause.
- **Timing constants** in `tts.py`: `LEAD` 1.6 s before the first word, `GAP`
  0.95 s between scenes, `SENT_GAP` 0.12 s between sentences, `TAIL` 5.0 s of end
  card. The total length is the sum of these plus the speech, and comes out at
  131.7 s.

## The animation engine (`src/index.html`)

There is one HTML page with a 1920×1080 `#stage`. `window.seek(t)` draws the frame
for time `t` as a **pure function of t**: there are no CSS transitions or timers.
That is why parallel rendering and single stills are both exact.

**Cue syntax**, used everywhere a time is needed:

| Cue | Means |
| --- | --- |
| `notes` | start of the `notes` narration |
| `notes@2` | start of its 3rd sentence (0-based) |
| `notes:sandbox` | estimated time the word "sandbox" is spoken (`#2` = second occurrence) |
| `notes$` | end of the `notes` narration |
| `…+0.4` / `…-0.2` | offset in seconds |

Words are lowercased, and hyphenated words stay whole (`in-place`, `forty-three`).
`render.py check` lists every cue that doesn't resolve.

**Declarative attributes:**

| Attribute | Effect |
| --- | --- |
| `data-in="cue" data-fx="…" data-d="0.7"` | entrance. fx: `up` `down` `left` `right` `pop` `fade` `blur` `zoom` `growx` (bars) `glitch` `stamp` |
| `data-out="cue"` | exit (0.45 s), also on elements without `data-in` |
| `data-words="seg@N"` | splits the text into words that each rise in when the voice says them |
| `data-type="cue" data-cps="40" [data-caret]` | typewriter; keeps the syntax-highlight spans |
| `data-count="85" data-in="cue" [data-dec="1"] [data-cd="1.4"]` | count-up |
| `data-scene="id" data-chap="NN\|Title"` | a scene section plus its chapter label |

**Hand-written motion** lives in `hooks(t)`: the opening headline lift, the
reveal hero shrinking to a header, the password dots flying into the vault, the
particle flows (`flow()`), the full-scan row highlight, the guard's terminal
shake, and the white flash on the two brand hits.

**Chrome:**

- chapter label (top left);
- small logo and "SE Enablement" tag (top right);
- progress bar (bottom);
- captions, single-line chunks built from the sentences (`CAPS`) that break after
  punctuation once a chunk passes 34 characters, or hard at 60.

**Background:** a canvas with drifting teal and mint glows, a rippling dot field
and rising motes. It shifts red during `problem` (and slightly during `guard`).
A giant, faint seal watermark drifts in the corner.

### Style: MariaDB plc (mariadb.com docs), not the community DevHub

deliberately not used.

## Audio (`src/audio.py`)

All audio is synthesized with numpy and scipy: there are no samples and no
licences to clear.

- **Score:** 100 BPM, D minor colour. The chords are Dm9 → B♭maj7 → Fmaj7 → Cadd9,
  two bars each.
  - Detuned additive pad (low-passed at 1.7 kHz).
  - 8th-note plucked arpeggio, panned left and right.
  - Kick, off-beat hats and a bass pulse from the reveal to the close.
  - **Problem section:** the arp drops out, a low drone comes in, and hats tick
    like a clock. A 3.2 s noise riser builds into the reveal.
  - **Close:** the beat drops, the pad and arp carry the logo, and the track fades
    over the last 2 s.
- **SFX** come from `.work/sfx.json`, which the page exports at `render.py check`
  time, so they always match the visuals:
  - a whoosh on every scene change;
  - impacts at 0.15 s, on the reveal and on the closing logo;
  - a thud on BLOCKED;
  - blips on `pop` elements and glitch bursts on the problem cards;
  - soft key clicks under the slower typewriters (cps ≤ 70).
- **Mix:**
  - The voice is high-passed at 70 Hz and peak-normalized.
  - The music is scaled to 0.38 × the speech RMS (`mg` in `audio.py`), then ducked
    by up to 55 % under the voice using a 250 ms envelope.
  - The SFX sit at 0.9.
  - Final `loudnorm` to I −16 LUFS / TP −1.5 dB happens in the mux.
  - Measured result: speech passages about −17 LUFS, the end card with music only
    about −25 LUFS, and −16.1 LUFS integrated.

## Fine-tuning recipes

| To change | Edit | Then run |
| --- | --- | --- |
| A line of narration | `src/narration.json` (keep the phonetic spellings; add caption mappings for new ones) | `./build.sh`; then check the cues in that scene, because a cue word you removed is reported by `check` |
| The voice or its speed | `build.sh` (the `tts.py af_heart 1.05` line) | `./build.sh` |
| Pauses between scenes | `LEAD` / `GAP` / `TAIL` in `src/tts.py` | `./build.sh` |
| Any visual | `src/index.html` | preview stills, then `./build.sh --no-tts` |
| Music level or arrangement | `src/audio.py` (`mg`, `section_gain` points, `CHORDS`) | `audio.py` + the mux line from `build.sh` (no re-render needed) |
| An SFX | `GEN` in `src/audio.py`, or the event list in `sfx.json` (`window.sfxEvents` in `index.html`) | `render.py check` → `audio.py` → mux |
| The logo or brand colours | `src/logo.png`, `:root` tokens in `index.html` | `./build.sh --no-tts` |

**Fast preview loop:**

```sh
../.cache/venv/bin/python -I src/render.py check             # cue errors, fonts, sfx.json, .srt
../.cache/venv/bin/python -I src/render.py stills 29 51 72.5  # PNGs in .work/stills/
```

To look at the page live, open `src/index.html` in Chrome and run `seek(42)` in
the console. Run `render.py check` first so `timeline.js` exists.

## Known limits and ideas

- Word timings are estimates (proportional to character position). They are good
  to about ±150 ms, which is fine for motion. For frame-exact lip sync, run a
  forced aligner (e.g. whisper-timestamped) over `vo.wav` and write the real word
  times into `timeline.json`.
- The illustrative outputs listed above could be replaced with real captured
  output from a recorded agent session.
- A 9:16 or 1:1 cut for social would need a second stylesheet. The cue system and
  timeline carry over unchanged.
- The closing link is the mariadb.com reference docs page. To change it, edit the
  `.u` span in the `close` scene and the last line of `narration.json`; the
  chips there cue off the spoken word `docs` (`close:docs+0.3`).
- Positioned labels that also animate: `applyFx` writes the element's
  `transform`, so a CSS `translateX(-50%)` centring on the same element is lost.
  Anchor such labels with `left`/`right` instead (see `.vlab--right`).
- Check the brand use of the logo and colours with Marketing before the video is
  shared outside Sales Engineering.
