Real options: (a) wrap long lines below the threshold (`white-space: pre-wrap` + a hanging indent) — the only one that shows everything at 320px; (b) shorten the sample in `docs/index.html` (`notes.sql` etc. — helps, but 42 chars is still ~342px); (c) leave the horizontal scroll, which now at least announces itself. **The `…` marker ships either way.**
4. (Optional, a11y) **Make the scrollable code blocks keyboard-reachable** — `tabindex="0"` + an accessible name, so they can be scrolled without a pointer. Applies to every code block on the site, not just the hero, which is why it was left out of the hero change.
5. **`mariadb-shell` must package pywin32 for Windows.** Its Windows packages (26.8.0 *and* 26.8.1, arm and x86 alike) ship no pywin32 — **26.9.0 and 26.9.1 are unverified**, nobody has opened their Windows tarballs — so `mcp start-server` dies with `ModuleNotFoundError: No module named 'pywintypes'` — reproduced by running the shell directly, no Codex or plugin involved, and fixed by hand with a `pip install pywin32` into the bundled Python 3.14. Until it is packaged, Codex's one-step install is only truly one step on macOS/Linux. Not filed yet (user declined).
6. **Transfer the remaining PRs from the fork** — `git fetch fork pull/<N>/head:pr-<N>-branch`, rebase onto `main`, verify, push to `origin`, open there. **Both are done** — fork PR 1 → #9, fork PR 2 → #7 — and the fork has no others, so this is finished unless new ones appear. Two lessons worth keeping: rebasing a fork PR onto a `main` that moved needs the overlaps checked **by hand**, because a clean rebase can silently revert newer edits in a restructured file.
7. **Once a stable (non-prerelease) `mariadb-shell` release exists**, drop the prerelease guidance from the main README and the 7 plugin READMEs. All four published releases are still prereleases, so `releases/latest` resolves to nothing and the launcher's prerelease fallback stays load-bearing.
